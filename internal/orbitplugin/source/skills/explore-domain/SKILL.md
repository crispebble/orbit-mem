# explore-domain

낯선 일은 만들기 전에 이해한다. 이해의 깊이는 일의 성격에 비례하며 작은 일에 모든 표·사례·질문을 강제하지 않는다.

## 1. 이미 있는 지식부터

1. 프로젝트의 결정·기록·설계 문서와 같은 주제의 기존 조사를 찾는다. 연결된 문서 도구가 있으면 그곳도 본다. 찾은 문서는 원문을 읽는다.
2. 저장소 문서, 지침 파일, 기존 코드의 이름과 시험을 본다.
3. 그래도 모르는 것만 새로 조사한다. 넓은 조사는 `research` 스킬을 쓴다.

## 2. 조사할 것

| 항목 | 질문 |
| --- | --- |
| 업무 흐름 | 일이 어떤 순서로 흘러가는가 |
| 관련자 | 누가 쓰고, 누가 결정하고, 누가 영향을 받는가 |
| 입력과 출력 | 무엇이 들어오고 무엇이 나가는가 |
| 상태 | 어떤 상태를 거치며 무엇이 상태를 바꾸는가 |
| 규칙 | 지켜야 할 업무 규칙, 제약, 규정 |
| 예외 | 흔하지 않지만 반드시 처리해야 하는 경우 |
| 숨은 전제 | 요청에 적히지 않았지만 당연하게 여겨지는 것 |

필요한 항목을 연결해 역할별 책임, 흐름과 상태 전환, 적용 규칙과 예외를 설명한다. 알 수 없는 항목은 미확인으로 남기고 누가 어떤 자료로 확인할지 적는다.

금지·의무는 행위자·행위·대상·조건·적용 범위에 맞게 해석한다. 인접한 역할의 겸직이나 다른 통제로 확대하지 않는다. 추가 통제는 확정 규칙과 분리한 제안·확인 사항으로 남긴다.

## 3. 사실·가정·미결정·미확인 나누기

- **사실**: 근거가 있다. 출처를 붙인다.
- **가정**: 근거는 없지만 합리적이다. 가정이라고 표시한다.
- **미결정**: 정해지지 않았고, 결정에 따라 결과가 달라진다.
- **미확인**: 사실·정책을 아직 확인하지 못했다. 확인할 담당자·자료와 그동안 확정할 수 없는 범위를 적는다.

섞어 쓰지 않는다. 가정을 사실처럼 쓰면 계획 전체가 기운다.

공식 기록의 권위·정책·업무 승인·책임 배분은 표현 형식이나 기술 기본값으로 확정하지 않는다. 제안은 미결정으로 남기고 결정 주체·확인 근거를 적는다.

## 4. 질문하기

- 자료로 조회할 사실, 사용자가 선택할 사항, 접근할 수 없는 필수 사실을 구분한다. 조회할 사실은 먼저 확인하고 이미 확정된 답은 되묻지 않는다. 접근할 수 없는 필수 사실이나 정책을 임의의 가정·정답으로 대신하지 않는다.
- 지금 진행을 막는 결정·필수 자료부터 묻는다. 결과가 같고 필수 사실·정책에 의존하지 않는 선택은 기본값과 근거를 밝힌다.
- 선택 질문에는 근거·선택지·추천을 붙이고, 자료 요청에는 필요한 자료와 그 이유를 붙인다. 선택 질문은 호스트 질문 도구가 있으면 그것으로 묻는다.
- 필요한 질문은 모으되, 한 질문에 독립 결정을 여러 개 숨기지 않는다. 자료로 풀 수 있는 것은 제외하고 지금 필요한 질문이 없으면 0개로 둔다. 나머지 미해결 사항은 후속 확인으로 남기며 모두 즉시 묻지 않는다.

## 5. 깊이 정하기

| 일의 성격 | 깊이 |
| --- | --- |
| 작은 수정, 익숙한 분야 | 관련 기록 확인 정도 |
| 새 기능, 낯선 업무 | 흐름·규칙·예외까지 |
| 되돌리기 어려운 일, 여러 관련자 | 관련자와 숨은 전제까지 모두 |

## 6. 대표 사례로 검증

복잡한 업무는 정상 흐름과 중요한 예외·경계를 드러내는 대표 2~3건을 따라간다. 각 사례를 **시작 조건 → 단계와 책임자·상태 변화 → 규칙에 따른 판단 → 기대 결과**로 연결해 빠진 책임·충돌·막힘을 확인한다. 단순히 사례 이름만 나열하지 않는다.

정책이 미정이거나 근거가 없으면 결과를 만들지 않는다. 가능한 분기와 각 분기를 결정할 담당자·자료, 확인 후 기대 결과를 판단할 조건을 남긴다. 사례 검토와 실제 실행·검증 결과는 구분한다.

## 7. 결과물

역할·흐름·상태·규칙·예외를 필요한 만큼 연결하고, 사실·가정·미결정·미확인과 확인 담당·자료를 짧게 정리한다. 복잡한 일은 대표 사례에서 확인한 내용과 남은 분기도 포함한다. 질문 목록은 지금 필요한 것만 둔다.

업무 분석·조사만 요청받았다면 보고로 마친다. 계획·구현까지 요청받은 경우에만 이 결과를 `plan` 스킬과 scoper에게 넘긴다.


## 서브에이전트로 실행 중일 때

역할 에이전트 안에서 이 스킬을 쓸 때는 사용자에게 묻기, 문서 저장, 승인 요청, 다른 역할에 맡기기를 직접 하지 않는다. 그런 단계는 반환에 '메인이 할 일'로 적는다. 이 스킬이 지금 자기 역할에게 맡기라고 하면 직접 수행한다.

## 점검 목록

- [ ] 이미 있는 지식을 먼저 찾았다.
- [ ] 사실·가정·미결정·미확인을 나누고 필요한 확인 담당·자료를 남겼다.
- [ ] 최종 결론·질문을 원문과 대조해 근거 없는 정책 확정이나 규칙 범위 확대가 없는지 확인했다.
- [ ] 지금 필요한 결정만 물었고, 추천을 붙였으며 이미 확정된 답은 되묻지 않았다.
- [ ] 깊이가 일의 성격에 맞고, 복잡한 업무는 대표 사례의 흐름·결과 또는 미정 분기를 확인했다.
