# 회고 제안 검토

밤사이 회고가 일지·후보 기억·짚을 점·제안을 남긴다. 제안은 사용자가 결정한다.

1. `proposals`로 대기 중인 제안을 읽는다.
2. 제안마다 종류, 제목, 이유, 대상 기억(제목·상태), 파일 반영이면 diff를 짧게 보여 준다. 많으면 종류별로 묶는다.
   - confirm: 후보를 확정할지
   - stale: 낡은 기억을 정리할지
   - merge: 겹치는 기억을 하나로 합칠지
   - reclassify: 옛 ISSUE·NOTE 기억의 종류를 바꿀지
   - apply_file: 확정 규칙을 Orbit 스킬 원본이나 지침 파일에 반영할지(diff)
   - direction: 다음 방향 제안을 결정으로 남길지
   - edit: 기억 하나의 제목·본문·태그·범위를 고칠지(diff)
   - revert: 승인했던 변경을 되돌릴지(효과 판정과 diff)
   - link: 관련 기억 둘을 이을지(두 기억 제목과 잇는 근거). 승인해도 기억 내용은 바뀌지 않는다
3. 사용자의 답을 받은 뒤에만 `proposal_decide`를 부른다. 승인·거절·고쳐서 승인(title·body) 중 사용자가 말한 대로 한다. 되돌리기·파일 반영·잇기는 고쳐서 승인할 수 없으니, 고치고 싶다고 하면 거절하고 직접 고치게 한다. 거절하거나 고쳐서 승인하면 사용자가 말한 이유를 note에 넣는다. 답이 모호하면 다시 묻는다.
4. 파일 반영을 승인하면 파일만 바뀐다. 커밋은 사용자가 한다. 바뀐 파일 경로를 알린다.
5. 끝나면 결정한 수와 남은 제안 수를 알린다.

터미널에서는 `oni proposals`로 같은 일을 할 수 있다.
