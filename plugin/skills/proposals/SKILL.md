# 감사 목록과 제안

AI가 배운 것은 증거가 쌓이면 스스로 확정되고, OpenOrbit 회고의 정리(낡음·합치기·대체·잇기·태그)는 승인 없이 적용돼 변경 효과 원장에 남는다. 사람은 승인 대기열을 처리하지 않는다. 보고 싶을 때 감사 목록을 보고 **틀린 것만 되돌리거나 고친다.** 사용자가 직접 말한 기억은 자동화가 고치지 못한다.

1. `proposals`에 `status=audit`을 주어 감사 목록을 읽는다. 기본(`pending`)은 사람의 결정을 기다리는 제안이다.
2. 감사 목록을 네 묶음으로 보인다. 묶음마다 머리에 이름과 건수를 쓴다.
   - 자동 변경(`changes`): 종류(confirm·merge·stale·supersede·link·retag·revert), 제목, 확정이면 증거(`seen_days` 다른 날 다시 나옴, `followed_verified` 검증된 일에서 따름, `verified_fact` 작업이 검증한 사실), 효과 판정(관찰 중·도움됨·해로움·효과 없음·섞임), 날짜. 해로움으로 판정돼 스스로 되돌린 것(`autoReverted`)은 따로 짚는다.
   - 어긋남(`conflicts`): 후보 제목과 어긋나는 사용자 규칙 제목, 표시한 쪽과 이유.
   - 반복 교정(`corrections`): 대상(기억·스킬·역할), 교정이 나온 세션 수와 기준, 최근 사용자 말. 스킬·역할이면 「하네스 개선 후보」로 짚는다(고치는 일은 openorbit 개발 과정이다. 이 PC에서는 교정을 기억으로 바로 따른다).
   - 대기 제안 수(`pending`): 있으면 `proposals`(기본)로 읽어 종류별로 묶어 보인다(고치기·재분류·파일 반영 diff·방향·사용자 말을 담은 기억에 닿는 정리, 증거 없는 확정).
   - 기준 횟수(`policy`)가 사용자 결정 대기(`policyPending`)면 그 사실을 한 줄로 알린다.
3. 사용자의 답을 받은 뒤에만 `proposal_decide`를 부른다.
   - 자동 변경이 틀렸으면 `decision=revert`, `id`에 그 `proposalId`(또는 `ledgerId`), `note`에 사용자가 말한 이유. 이전 판으로 돌아가고(자동 확정은 후보로), 같은 변경은 자동화가 다시 하지 않는다.
   - 어긋남: 후보가 맞으면 `memory_update`(`action=confirm`, 사용자 말을 `userQuote`에), 틀리면 `action=stale`, 문제없다고 하면 `decision=dismiss`(`id`에 `f-…`).
   - 반복 교정을 봤다고 하면 `decision=dismiss`(`id`에 `correction:…` 키). 그 뒤 교정만 다시 센다.
   - 사용자 말을 담은 기억에 닿는 대기 제안을 결정하거나 어긋남 표시를 닫을 때는 사용자가 그렇게 하라고 한 말을 `userQuote`에 그대로 넣는다.
   - 대기 제안은 `approve`·`reject`. 같은 답을 받은 제안 여럿은 `ids`에 모아 한 번에 결정하고, 실패한 것은 이유와 함께 그대로 알린다. 고쳐서 승인(title·body)은 `id`로 하나씩 한다. 되돌리기·파일 반영·잇기·태그 정리는 고쳐서 승인할 수 없다. 거절하거나 고쳐서 승인하면 이유를 `note`에 넣는다.
   - 답이 모호하거나 어느 항목을 가리키는지 분명하지 않으면 다시 묻는다.
4. 파일 반영을 승인하면 파일만 바뀐다. 커밋은 사용자가 한다. 바뀐 파일 경로를 알린다.
5. 끝나면 되돌린 수, 닫은 수, 결정한 수와 남은 것을 알린다.

터미널에서는 `orbit-mem audit`(되돌리기 `audit revert <id>`, 확인함 `audit dismiss <id>`)과 `orbit-mem proposals`로 같은 일을 할 수 있다.
