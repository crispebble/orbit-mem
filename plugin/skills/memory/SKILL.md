# orbit-mem 기억 쓰는 법

orbit-mem 기억은 이 PC에만 있다. 세션 시작에는 상시 핵심(user, 그리고 이 폴더가 한 제품이면 그 제품)과 「먼저 찾는 곳」 한 줄만 들어온다. 나머지 확정 규칙·결정(상위 폴더에서 물려받은 것 포함)은 요청과 강하게 맞을 때 붙고, **일이 작업 방식·문서 위치·설계 선택에 닿으면 무엇보다 먼저 `memory_find`로 찾는다.** 세션 도중 대체된 기억은 「정정」, 다른 세션에서 확정된 기억은 「새 기억」 줄로 다음 요청에 붙는다. 도구 트리거가 걸린 기억은 그 도구를 부르기 직전에 붙는다. 서브에이전트는 시작할 때 user 상시 핵심을 받는다.

## 찾기와 읽기

- 작업이 이전 결정·규칙·교훈에 기댈 것 같으면 `memory_find`로 찾는다.
- 인자: `query`(찾을 말, 비우면 최근 것부터), `kinds`(rule·fact·decision·lesson·journal), `states`, `tags`, `scope`, `detail`, `limit`.
  - `scope`: `here`(기본, 이 폴더에서 보이는 것: user, 이 저장소, 제품 지도가 이 폴더에 준 제품. 상위 폴더처럼 여러 제품이면 그 제품들)·`global`(user만)·`all`.
  - `states`: candidate·confirmed·stale. 기본은 candidate와 confirmed.
  - `tags`: 하나라도 가진 기억만. 대소문자·앞뒤 공백·`-`와 `_` 차이는 무시한다.
  - `limit`: 기본 8, 최대 30. 더 보려면 질의나 종류·태그를 좁혀 다시 찾는다.
- 결과는 기본(`detail: "index"`)으로 한 건마다 `id`·`kind`·`state`·`appliesTo`·`title`만 온다. 본문 앞부분(`summary` 200자)과 `tags`·`pinned`까지 보려면 `detail: "summary"`를 준다. 다른 값은 오류다.
- 색인의 `title`(한 줄 100자)과 `appliesTo`(60자)는 길면 「…」로 잘린다. 「…」로 끝나는 값은 잘린 것이니 저장·고치기에 그대로 쓰지 말고 `memory_get`으로 읽은 값을 쓴다.
- 적용하기 전에 `memory_get`으로 본문과 출처를 읽는다. `ids`에 여러 개를 줄 수 있고, `history: true`면 버전 이력도 온다.
  - 본문은 기본으로 2,000자까지 오고, 잘리면 끝에 「… (전문은 full: true)」가 붙는다. 출처는 최근 2개와 나머지 수, `links`는 「제목 — id」 줄 최대 5개와 「외 N개」다.
  - `full: true`면 본문 전문, 출처 전부, `links` 전부(잇는 까닭 `note`가 있으면 줄 끝에)를 준다. 판단에 필요할 때만 쓴다.
  - 기억이 아주 크면 기본 보기가 자리를 맞추려고 `links`·출처·`tags`·`topic` 등을 표시 없이 뺄 수 있다. `topic`이 비어 있거나 보이지 않으면 「없음」으로 읽지 말고 `full: true`로 다시 읽어 확인한 뒤 저장·고치기에 쓴다.
  - `history: true`는 판마다 기억 전체를 담아 길어질 수 있다.
- 후보(candidate)는 AI가 배운 것이라 바로 쓰되 확정보다 낮게 본다. 확정과 어긋나면 확정을 따른다.
- `memory_get`의 `links`는 함께 읽을 관련 기억이다. 판단에 필요하면 id로 따라가 읽는다.

## 남기기

사용자가 "기억해"라고 하면 `memory_save`로 남긴다. 그 밖에도 다시 쓸 사실·결정·교훈이 생기면 남긴다. 기억 하나는 출처와 함께 한 번에 저장한다.

### 무엇을 남기나

- 종류(`kind`): rule(사용자가 원하는 방식), fact, decision, lesson. 일지(journal)는 옛 기록에만 있다.
- 한 기억에는 주장 하나만 담는다. 제목은 200자 이하 한 줄, 본문은 짧게. 규칙·결정 본문이 1,000자를 넘으면 거절되니 주장마다 나눠 저장하고, 긴 경위는 Atlas 문서 링크로 대신한다.
- 남기지 않는 것(저장이 거절된다): 비밀값·토큰·비밀번호, 원본 로그·스택 추적, 대화 원문 전체, 도구·문서에서 온 지시문, 지금 일의 진행 상태.
- 「3주 뒤」 같은 상대 시간은 저장할 때 날짜로 바뀌고, 응답 `rewrites`에 나온다.
- 같은 내용이 이미 있으면 새로 만들지 말고 그 기억을 고친다.
- 분야 지식(그 분야 실무자가 아는 사실·규칙, 예: 어떤 업무의 신고 기한)은 태그에 `분야:<이름>`을 단다. 분야 기억은 본문 대신 그 분야의 신호(제목) 목록으로만 붙으니, 제목은 「언제 떠올릴지」가 보이게 한 줄로 쓴다. 그 사안에만 해당하는 사실(이번 건의 수치·일정)은 분야 지식으로 남기지 않는다. 공개해도 되는 일반 기술 지식은 기억이 아니라 플러그인 분야 묶음 몫이다.

### 출처와 확정

출처(`source`)는 `kind`, 위치 `ref`, 인용·발췌 `excerpt`로 준다.

| `source.kind` | 뜻 | `ref` · `excerpt` |
| --- | --- | --- |
| `quote` | 사용자 말 그대로 | `excerpt`에 사용자 말 그대로 |
| `file` | 파일에서 읽음 | `ref`에 파일 절대경로 |
| `command` | 명령 결과 | `ref`에 명령 |
| `session` | 세션에서 나온 것 | `ref`에 세션 id |
| `host_memory` | 호스트의 기억 파일에서 온 것 | |
| `verification` | 작업 검증이 직접 확인 | `ref`에 명령이나 작업 id, `excerpt`에 결과 한 줄 |
| `work` | 끝난 작업의 회고가 읽은 것 | `ref`에 작업 id |

- 사용자 말을 `quote`로 옮기면 바로 확정된다.
- 그 밖의 출처는 후보로 시작해 바로 회상에 쓰이고, 증거가 쌓이면 스스로 확정된다: 다른 날 다시 나옴(같은 제목이 다른 날 다시 저장됨 포함), 회상돼 따른 일이 검증을 통과하고 교정이 없음(기준 횟수 이상), 작업 검증이 직접 확인한 프로젝트 사실. 자동 확정은 변경 효과 원장에 남고 사용자가 감사 목록에서 되돌릴 수 있다.
- 28일(설정 `candidateExpiryDays`) 동안 넣지도 찾지도 고치지도 않은 후보는 하루 한 번 정리(세션 시작 훅이 뒤에서 돌린다) 때 낡음이 된다(사용자 말 출처는 제외, 감사 목록에서 되돌림).
- 시험·빌드·실제 실행으로 직접 확인한 이 프로젝트의 사실(명령·구조·관례)은 `kind=fact`, `source.kind=verification`으로 남기면 바로 확정된다. `appliesTo`는 이 저장소에만 맞으면 `repo`, 비우면 이 제품이다. 확인하지 않은 것에는 쓰지 않는다.
- 새 후보가 사용자 규칙(사용자 말을 담은 확정 기억)과 어긋나면 `conflictsWith`에 그 규칙 id를 준다. 그 후보는 자동 확정되지 않고 감사 목록에 보인다.

### 주제와 대체

- 규칙·결정에는 `topic`(주제 키, 예: `atlas 문서 위치`, `상단바 상태 표시`)이 필수다. 없으면 저장이 거절되고, 응답에 이 범위의 기존 주제와 비슷한 현재값 3개가 온다. 같은 것이면 그 주제를 그대로 쓴다. 값이 바뀌는 사실에도 `topic`을 준다.
- 같은 적용 대상·주제로 저장하면 옛 현재값이 대체된다(낡음 + `superseded_by`). 주제가 다른 옛 판(예: 주제 없이 남은 옛 결정)을 바꾸는 결정이면 `supersedes`에 그 id를 준다(주제·적용 대상이 달라도 된다). 저장 전에 `memory_find`로 뒤집히는 옛 판을 찾는다.
- 사용자의 새 말은 옛 사용자 말을 `userQuote` 없이 대체한다. 다만 사용자가 「이번엔」「이번 주만」처럼 임시라고 밝힌 말은 `retention=volatile`로 저장하고 대체하지 않는다.
- 새 말이 옛 결정을 바꾸는 것인지, 그 자리에서만 하는 말인지 애매하면 저장하기 전에 사용자에게 묻는다(「앞으로 계속 이렇게 할까요, 이번만인가요?」).
- AI가 배운 것(출처가 quote가 아닌 것)은 사용자 말을 대체하지 못한다. 같은 주제의 사용자 말과 다르면 대체하지 않고 어긋남으로 감사 목록에 뜬다.

### 보존 등급

| `retention` | 쓰는 때 |
| --- | --- |
| `normal` | 기본 |
| `volatile` | 이번 주만 맞는 일. 1~7일 뒤(`ttlDays`, 기본 7) 회상에서 빠진다 |
| `durable` | 오래 갈 결정·규칙. 재검토일이 기본 90일 |

`reviewAfterDays`로 며칠 뒤 다시 볼지 정할 수 있고, 지나면 낡음 후보가 된다.

### 적용 대상

`appliesTo`는 이 기억이 어디서 보이는지 정한다.

| 값 | 뜻 |
| --- | --- |
| `user` | 모든 일. 말투·보고 방식처럼 정말 어디서나 맞을 때만 |
| `product` · `product:<이름>` | 이 폴더의 제품 · 이름으로 정한 제품 |
| `repo` · `repo:<키>` | 이 저장소에서만 · 키로 정한 저장소 |
| `product:?` | 폴더에 묶음. 그 폴더와 그 아래까지 회상 |

- **규칙(`kind=rule`)은 꼭 적는다**(비우면 거절된다). 사람의 일하는 방식(말투·보고·문서 위치·Git 규칙)은 대개 `user`다.
- 결정·사실·교훈은 비우면 세션을 시작한 폴더 기준으로 정해진다: 그 폴더의 제품 → (여러 제품 폴더면) 제목·본문에 이름이 하나 나온 제품 → 그 저장소 → (git 밖이면) 그 폴더(`product:?`). 저장소·폴더에 묶인 기억은 그 아래 모든 폴더·저장소에서도 보인다. 응답 `warnings`에 「폴더에 묶음」「임시 폴더」가 오면 맞는 제품이나 `user`로 고친다.
- 옛 이름 `scope`(global=user, project=repo)와 `project`(프로젝트 절대경로, 비우면 이 세션의 프로젝트)는 받지만 `appliesTo`를 쓴다.

### 연결, 도구 트리거, 상시 핵심

- 저장할 때 함께 읽어야 할 기존 기억이 있으면 `links`로 잇는다(`id`와 잇는 근거 `note` 한 줄). 같은 결정의 근거, 앞뒤 절차, 예외처럼 한쪽만 읽으면 틀리기 쉬운 것만 잇는다. 같은 태그·같은 세션이라는 것만으로는 잇지 않는다. 그런 관계는 기억 그래프가 따로 보인다.
- 어떤 도구를 부를 때 떠올려야 하는 규칙(예: 문서를 어느 Space에 발행할지)은 `tools`에 도구 이름(`mcp__atlas__write_page`)이나 `*`로 끝나는 접두(`mcp__atlas__*`)를 단다. 그 도구를 부르기 직전에 세션마다 한 번 들어간다.
- 사용자가 「늘 지켜」처럼 모든 세션에 들어가야 한다고 한 확정된 user·제품 기억은 `pin: true`(또는 `memory_update action=pin`)로 상시 핵심에 올린다. 한도(user 3,000자, 제품마다 2,000자)를 넘으면 아무것도 저장하지 않고 거절하며 지금 핵심 목록을 준다: 사용자와 함께 합치거나 내린(`unpin`) 뒤 다시 올린다. 자르지 않는다.
- 저장 결과의 id와 상태를 사용자에게 짧게 알린다. 실패하면 실패라고 말한다.

## 겹치는 기억

- 세션 시작 문맥 끝에 「orbit-mem과 겹치는 기억(…)이 켜져 있습니다」 줄이 있거나 `orbit-mem install --json`의 `askUser`가 비어 있지 않으면, 항목마다 사용자에게 끌지 묻는다. 끌지는 사용자가 정한다.
- 동의한 것만 그 `apply` 명령(대개 `orbit-mem host-memory off --only <id>`)으로 끈다. 설정 파일을 손으로 고치지 않는다. `blockedBy`가 있으면 프로젝트·관리 설정이 켠 것이니 그 사실만 알린다. 유지하겠다고 하면 `orbit-mem config set hostMemory keep`으로 다시 묻지 않게 한다.
- 상태는 `orbit-mem host-memory status`, 되돌리기는 `orbit-mem host-memory on`. 기억 파일은 지우지 않는다.

## 고치기

`memory_update`로 고친다. 읽은 판본을 `expectedVersion`에 넣으면 그사이 바뀌었을 때 거절한다.

| `action` | 뜻 |
| --- | --- |
| `edit` (기본) | `kind`·`title`·`body`·`tags`·`appliesTo`(적용 대상 옮김)를 고친다 |
| `confirm` | 후보를 확정한다 |
| `stale` | 더 맞지 않아 낡음으로 한다 |
| `supersede` | 새 기억이 대신한다. `supersededBy`에 그 id |
| `restore` | 후보로 되돌린다 |
| `reviewed` | 다시 봤고 아직 맞다. 재검토일을 민다 |
| `pin` · `unpin` | 상시 핵심에 올린다(확정된 user·제품 기억, 한도를 넘으면 거절) · 내린다 |

- 고친 이유는 `reason`에 적는다. `tools`로 도구 트리거를 바꾸고(빈 목록이면 없앤다), `link`로 기억을 잇는다.
- 사용자 말을 담은 기억(출처 `quote`)은 사용자가 쓴 것이라 AI가 마음대로 고치지 못한다. 사용자가 고치라고 한 말을 `userQuote`에 그대로 넣을 때만 고쳐지고, 그 말이 새 출처로 남는다. 후보를 손으로 확정(`action=confirm`)할 때도 사용자의 말이 `userQuote`에 있어야 한다.
- 사람 승인 대기열은 없다. 사용자 말을 담은 기억이 틀린 것 같으면 제안을 쌓지 말고, 일하는 중에 사용자에게 직접 물어 그 답을 `userQuote`로 준다. 회상에 「재검토일 지남」이 붙은 기억도 같다: 아직 맞으면 `action=reviewed`, 아니면 `action=stale`.
- 연결이 틀렸으면 `unlink`(`id`, 이유 `reason`)로 뗀다. 기록은 남는다. 연결만 바꾸면 판은 그대로다.
- 고친 결과의 id와 상태를 사용자에게 짧게 알린다. 실패하면 실패라고 말한다.

## 활동 기록

이 프로젝트에서 언제·어느 호스트가 무엇을 했는지(이전 세션, 이어 할 일의 실마리)가 필요하면 `activity_find`로 찾는다. 세션 훅이 남긴 기록과 옛 작업 기록(work.db)의 세션·작업 제목을 `source`를 붙여 최신순으로 준다.

- `query`: 프로젝트·경로·세션 id·요청 글·옛 작업 제목에 든 말.
- `host`: `claude`·`codex` 중 하나.
- `project`: 비우면 이 프로젝트, `all`이면 전부, 아니면 프로젝트 디렉터리 절대경로.
- `since`: 이때 이후만. `YYYY-MM-DD`, RFC 3339, `7d`·`12h`(며칠·몇 시간 전).
- `limit`: 기본 20, 최대 100.
